# Escalation boundary — what the loop must NOT auto-apply

The loop auto-applies codex's findings only when they are safe. Anything below is **escalated to Korab** instead of being applied silently. The reason is blast radius: these files either configure the whole build, are a single source of truth other files derive from, or change externally observable behaviour. A wrong auto-edit here is expensive to notice and undo, which defeats the point of a headless loop.

When a finding touches any of these, surface it (file, line, what codex suggested, why it is risky) and stop applying that finding. Keep applying the safe ones.

## Protected files (from AGENTS.md §3 — orchestrator-only)

- `astro.config.*` (any extension)
- `package.json`
- `pnpm-lock.yaml`
- `tailwind.config.*`
- `postcss.config.*`
- `tsconfig.json` and any `tsconfig.*.json`
- `keystatic.config.ts`
- `.env*` (all environment files)
- `.nvmrc`, `.tool-versions`
- any `index.ts` / `index.tsx` barrel file (auto-generated by `scripts/gen-barrels.ts`)
- everything inside `.claude/`
- `scripts/gen-trail-register.ts`
- `src/content/trail-register/commits.seed.json`

## Single-source-of-truth files (from AGENTS.md §6a)

- `src/lib/status.ts` — Korab's location / relocation / citizenship / work-authorization facts. The hero readout, about page, and JSON-LD all import from it.
- `public/llms.txt` — hand-written mirror of `STATUS`; `tests/status-sync.test.ts` fails CI if it drifts. Never let codex edit one without the other.

## Behaviour-changing findings (regardless of path)

Simplifications that preserve behaviour are the safe, expected case. Escalate instead when a finding would change what the code *does*, not just how it reads:

- changes a public component prop, exported function signature, or return shape
- alters rendered output, routing, redirects, or SEO/meta/OG output
- changes control flow in a way that could shift a Playwright visual baseline or an axe/Lighthouse result
- deletes or rewrites a test's assertions (as opposed to the code under test)
- touches data generation (`scripts/gen-*.ts`) or content collection schemas
- suggests deleting or removing an entire file, or hinges on author intent ("this
  file looks unused", "this feature seems unnecessary") — whether something belongs
  is Korab's call, not the loop's

If unsure whether a finding is behaviour-preserving, treat it as behaviour-changing and escalate. `verify:all` is the backstop, but escalation is cheaper than a reverted loop.
